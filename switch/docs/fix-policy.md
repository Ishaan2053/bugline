# Fix policy

What the fixer may change, how, and what it posts when it is done. The fixer starts only after the
PM approves a ticket in its thread in `bugline-eng`, for example:

```
@fixer go on BL-1, keep it to the share handler, add a regression test
```

The PM's message sets the scope. If it names a handler or a file, stay inside it.

## Scope

- One ticket per branch, one PR per ticket.
- One handler per fix: the route function or the helper it calls that the reproducer named in
  `Likely cause`, in `demo-app/app/`. If the fix needs a second handler, stop and ask the PM in the
  thread.
- Never touch the database schema (`SCHEMA` in `demo-app/app/db.py`), `demo-app/seed.py`, any
  `.db` file, or data of any kind. There are no migrations in this app; do not add any.
- Never change existing tests to make them pass. Never delete a test.
- No new dependencies. No refactors, renames or formatting changes outside the lines you fix.
- Leave the other seeded faults alone. Fix only the ticket you were given.

## Steps

Work in your own working directory (`C:\bugline-agents\bugline-fixer`), in a clone of
`https://github.com/Ishaan2053/bugline`. Set up the venv the same way as
[repro-checklist.md](repro-checklist.md#1-environment).

1. `git checkout main` and `git pull --ff-only`.
2. Make the branch `fix/demo-app-bl-<n>-<slug>`, where `<slug>` is two to four words of the title
   in lowercase with hyphens. Example: `fix/demo-app-bl-1-share-link-zero-expenses`.
3. Write the regression test first, in `demo-app/tests/test_app.py`, using the fixtures in
   `demo-app/tests/conftest.py`. Name it after the behaviour, not the ticket
   (`test_share_summary_for_member_who_paid_nothing`). Run it and see it fail.
4. Fix the handler. Run `pytest -q` from `demo-app/`. Every test must pass.
5. Run `ruff format .` and `ruff check .` from `demo-app/`. Both must be clean.
6. Commit with the message `BL-<n>: <summary>`. Use the git identity already configured in the
   working directory. Add no `Co-Authored-By` or "generated by" lines.
7. Push the branch and open a PR to `main`:
   - Title: `BL-<n>: <summary>`, the summary under 60 characters.
   - Label: `demo-app`.
   - Body: what was wrong, what changed, the regression test's name, and the last line of
     `pytest -q`.
   - Do not merge it. The PM reviews and merges.

If any step fails and you cannot fix it inside the scope above, post what failed in the thread and
stop.

## What to post when done

Reply in the ticket's thread, under 10 lines. The first line mentions the front desk, names the
ticket once, and has the full PR URL:

```
@frontdesk BL-1 is fixed: https://github.com/Ishaan2053/bugline/pull/12
Change: demo-app/app/main.py, share(): average is 0 for a member with no expenses.
Test: test_share_summary_for_member_who_paid_nothing
pytest -q: 9 passed
```

- Follow `@frontdesk` with a space. `@frontdesk.` does not reach it, because a period can be part
  of a name.
- Name only this ticket's id in the message. The front desk reads `BL-<n>` and the
  `https://github.com/.../pull/<number>` link from it to close the ticket and tell the reporter.
- The PR URL is the full `https://github.com/...` link, not `#12`.
