# Fix policy

What the fixer may change, how, and what it posts when it is done. The fixer starts only after the
PM approves a ticket in its thread in `$eng_room`, for example:

```
@fixer go on $ticket_prefix-1, keep it to the share handler, add a regression test
```

The PM's message sets the scope. If it names a handler or a file, stay inside it.

## Scope

- One ticket per branch, one PR per ticket.
- One handler per fix: the route function or the helper it calls that the reproducer named in
  `Likely cause`, in `$app_dir/app/`. If the fix needs a second handler, stop and ask the PM in the
  thread.
- Never touch the database schema (`SCHEMA` in `$app_dir/app/db.py`), `$app_dir/seed.py`, any
  `.db` file, or data of any kind. There are no migrations in this app; do not add any.
- Never change existing tests to make them pass. Never delete a test.
- No new dependencies. No refactors, renames or formatting changes outside the lines you fix.
- Leave the other seeded faults alone. Fix only the ticket you were given.

## Steps

Work in your own working directory (`$fixer_workdir`), in a clone of
`$repo_web`. Set up the venv the same way as
[repro-checklist.md](repro-checklist.md#1-environment).

1. `git checkout $default_branch` and `git pull --ff-only`.
2. Make the branch `fix/$app_area-${ticket_slug}-<n>-<slug>-<stamp>`, where `<slug>` is two to four words of
   the title in lowercase with hyphens and `<stamp>` is the UTC time you start, from
   `date -u +%m%d%H%M`. Example: `fix/$app_area-${ticket_slug}-1-share-link-zero-expenses-11071432`. The stamp
   matters: ticket numbers restart at `$ticket_prefix-1` after a demo reset, and the branches of earlier PRs
   stay on GitHub. Without it a new branch can take an old name, and the push fails.
3. Write the regression test first, in `$app_dir/tests/test_app.py`, using the fixtures in
   `$app_dir/tests/conftest.py`. Name it after the behaviour, not the ticket
   (`test_share_summary_for_member_who_paid_nothing`). Run it and see it fail.
4. Fix the handler. Run `$test_command` from `$app_dir/`. Every test must pass.
5. Run `ruff format .` and `ruff check .` from `$app_dir/`. Both must be clean.
6. Commit with the message `$ticket_prefix-<n>: <summary>`. Use the git identity already configured in the
   working directory. Add no `Co-Authored-By` or "generated by" lines.
7. Push the branch and open a PR to `$default_branch`:
   - Title: `$ticket_prefix-<n>: <summary>`, the summary under 60 characters.
   - Label: `$app_area`.
   - Body: what was wrong, what changed, the regression test's name, and the last line of
     `$test_command`.
   - Do not merge it. The PM reviews and merges.

If any step fails and you cannot fix it inside the scope above, post what failed in the thread and
stop.

## What to post when done

You do not close the ticket. The reproducer checks your PR first, and only its `Verified` line
closes the ticket and tells the reporter.

Reply in the ticket's thread, under 10 lines. The first line asks the reproducer to verify, in
exactly this form, with the full PR URL and your branch:

```
@reproducer please verify $ticket_prefix-1 on PR $repo_web/pull/12 (branch fix/$app_area-${ticket_slug}-1-share-link-zero-expenses-11071432)
Change: $app_dir/app/main.py, share(): average is 0 for a member with no expenses.
Test: test_share_summary_for_member_who_paid_nothing
$test_command: 9 passed
```

- The `agents/coder` program sees that first line and hands your reply to whoever holds the
  `reproducer` role. If nobody does, it says so in the thread.
- Name only this ticket's id in the message.
- The PR URL is the full `https://github.com/...` link, not `#12`.
